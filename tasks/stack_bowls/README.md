# 叠三碗任务包 v0.3

## 谁负责决策
本文件是开发前编写的任务规划。小主机负责队列，千问3.8 Max负责在线观察、选择手臂和抓点、执行、故障诊断及候选修复。记录方案来源为预设规划；汇报为“预设规划＋千问执行”。若要测千问自主规划，另开条件，只提供目标和通用工具。此文件不是已验证的叠碗技能。

## 入场与选择底碗
从原生 reset 开始，读取本次任务的真实动作上限、机器人初始姿态及成功判据。先选privileged开发组。按实际可用接口给三只碗分配回合内稳定编号，记录碗口中心、碗轴、桌面、双臂坐标变换及夹爪开度。单位统一米和弧度。若对象数、坐标系或模型实际部署无法核实，进入blocked。
对三个可能的底碗分别尝试两只上层碗的抓取、搬运和放置预规划。优先选两次都可达、沿途避开另一只碗且底碗稳定的方案。同分时选总路径短者。没有可行解时允许尝试换手或调整底碗位置，单独记录额外动作。用观察或测量得到碗尺寸，不在控制器写死场景坐标。

## 一次搬运的决策清单
|阶段|千问要决定什么|程序与证据|失败后的分支|
|---|---|---|---|
|接近|选可达碗沿、手臂和接近方向|计算预抓姿态；记实际末端误差、剩余净空|规划拒绝则换抓点，保留拒绝原因|
|抓持|何时闭爪|记录闭爪前后开度、碗相对夹爪姿态|疑似夹空时先验证|
|试抬|是否可以搬运|短距上移；验证碗随动、相对姿态稳定、旁碗未动|未随动则放回撤爪；滑落则按新姿态重新定位|
|搬运|选安全高度和横移路线|按持碗外形校验净空，保存首次滑移帧|滑移停止横移；若旧堆叠被碰动则重新测量|
|对齐|把碗中心对准哪一点|补偿抓点到碗中心的偏移，复查底碗方向|末端到了但碗心偏离时修正目标|
|释放|何时松开和撤臂|下降、松开、撤爪后再观察，验证嵌套、稳定且未被带起|区分卡沿、推走底碗、撤臂碰撞|
|第三碗与归位|第二只是否已落稳|已落稳才重复搬运；三碗叠好后双爪张开并归位，读取原生终态|外观正确但未成功时保存判定分解|

位置、滑移、稳定时间阈值先从当前任务配置获取；缺失时在开发初态标定，连同单位、来源和配置SHA记录，再冻结用于比较。阶段记录含 run、stage、目标碗、arm、预期、实际、动作序号、证据路径、允许的回退及剩余步数。

## 小主机的续跑规则
1. 核对已有健康job、当前commit、Max实际路由及授权资源。先单worker完成一个原生回合；成功或科学失败均保留。服务或适配失败不计作机器人动作失败。
2. 原生证据完整后，进入普通/杂乱开发初态配对。只并行独立episode，同一episode始终只有一个控制者。各worker隔离仿真、模型会话、日志和输出。并发上限取现场已授权卡数、实测显存容量和模型端限流三者最小值；未知时保持1。并发由作业队列承担。
3. 每次只有一个写入者晋升候选。run键包含模型、代码、配置、权限、seed、layout和重复编号，重启按句柄查终态。每阶段最多一次有依据的回退，每个失败簇首批最多三项候选。记录假设与反证，先在原失败初态比较，再从头回归已成功初态；候选通过才启动下一批。
4. 下一批可在已有预算内自动开始。用尽已授权预算、模型返回非Max、持续基础设施失败、无进展达到候选上限或状态归属不清时，保存现场并停止派新作业。事先封存的布局仅用于冻结后验收。
5. 输出一个README汇总不同权限组的原生成功分子分母、超时、成本、人工介入和代表录像。首轮交付需含原生reset、首次动作、阶段轨迹、模型和终态回执。测试fixture与实测分别存放。
